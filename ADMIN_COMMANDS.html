📦 Account Inventory Management
ACCOUNT_INVENTORY Topic
Add Available Account
Add a game account to the available pool so users can load it
Format:
ACCOUNT | game=GameA | username=user123 | password=pass456 | status=AVAILABLE
Example:
ACCOUNT | game=GameB | username=john_doe | password=SecurePass789 | status=AVAILABLE
Notes: Bot will create a canonical record that can be edited later. Status must be AVAILABLE for the account to be assignable to users.
ACCOUNT_INVENTORY Topic
Mark Account as Assigned
Mark an account as assigned to a specific user (removes from available pool)
Format:
ACCOUNT | game=GameA | username=user123 | password=pass456 | status=ASSIGNED | assigned_to=USER_ID | assigned_at=TIMESTAMP
Example:
ACCOUNT | game=GameA | username=john_doe | password=SecurePass789 | status=ASSIGNED | assigned_to=123456789 | assigned_at=2026-02-01T10:30:00Z
Notes: The assigned_to must be a valid user ID. The assigned_at should be ISO format timestamp.
💳 Payment Configuration
PAYMENT_CONFIG Topic
Add / Update Payment QR Code
Upload a payment QR code (photo or document) for a specific game and payment method. Can be used for multiple methods.
Format:
PAYMENT_QR | game=GameA | method=CashApp
Example:
Upload a photo/document with caption: PAYMENT_QR | game=GameA | method=CashApp
Or: PAYMENT_QR | game=GameB | method=Zelle
Notes:
  • Must attach a photo or document to the message
  • Each game+method combination can have its own QR
  • Re-uploading with the same game+method will replace the previous QR
  • Common methods: CashApp, Zelle, Chime, Venmo, etc.
PAYMENT_CONFIG Topic
Disable Payment Method
Disable a payment method so it no longer appears to users (but QR data is preserved)
Format:
PAYMENT_METHOD_DISABLE | game=GameA | method=CashApp
Example:
PAYMENT_METHOD_DISABLE | game=GameA | method=CashApp
Notes: Users will not see this method when they select payment options. The QR data remains stored and can be re-enabled.
PAYMENT_CONFIG Topic
Enable Payment Method
Re-enable a previously disabled payment method
Format:
PAYMENT_METHOD_ENABLE | game=GameA | method=CashApp
Example:
PAYMENT_METHOD_ENABLE | game=GameA | method=CashApp
Notes: Once enabled, the method will appear in the user's payment method selection menu.
✅ Approval Controls
LOAD_APPROVALS or WITHDRAW_APPROVALS Topic
Approve Load / Withdrawal Request
Click the ✅ Approve button on a pending request to approve it
How:
1. Navigate to LOAD_APPROVALS or WITHDRAW_APPROVALS topic
2. Find the pending request
3. Click the ✅ Approve button
4. User receives confirmation and balance is updated
Notes: Approvals are logged with your admin identity and timestamp.
LOAD_APPROVALS or WITHDRAW_APPROVALS Topic
Reject Load / Withdrawal Request
Click the ❌ Reject button on a pending request to reject it with a reason
How:
1. Navigate to LOAD_APPROVALS or WITHDRAW_APPROVALS topic
2. Find the pending request
3. Click the ❌ Reject button
4. Submit your rejection reason in the next step
Notes: The rejection reason is visible to the user. You can cancel a rejection by clicking ↩ Cancel Reject.
📣 Promotions & Broadcasts
PROMOTIONS Topic
Send Promotion to All Users
Broadcast a promotion message to all known users in the system
Method 1 - Inline:
/promo This is your promotion text here
Method 2 - Multi-line:
1. Send /promo in PROMOTIONS topic
2. Send your promotion text as the next message
Example:
/promo 🎉 NEW BONUS: Load $100 and get 20% extra credit!
Or:
1. Send: /promo
2. Follow up with: 🎉 NEW BONUS: Load $100 and get 20% extra credit!
Notes: All known users will receive a DM with the promotion. Delivery attempts are logged with success/failure stats.
✉️ Direct User Messages
PROMOTIONS Topic
Send Message to Specific User
Send a direct message to a specific user by their user ID
Method 1 - Inline:
/msguser USER_ID Your message text here
Method 2 - Step by Step:
1. Send /msguser in PROMOTIONS topic
2. Send the target User ID as next message
3. Send the message text as the final message
Example:
/msguser 123456789 Hi! Your account has been verified. You can now load balance.
Or:
1. Send: /msguser
2. Send: 123456789
3. Send: Hi! Your account has been verified. You can now load balance.
Notes: The user ID must be a valid Telegram user ID. Messages are sent via bot DM. Delivery is logged.
🎫 Support Tickets
SUPPORT_TICKETS Topic
Resolve a Support Ticket
Mark a support ticket as resolved (closes the ticket and stops accepting replies)
How:
1. Open SUPPORT_TICKETS topic
2. Find the ticket you want to resolve
3. Click the ✅ Resolve button
4. Ticket status changes to RESOLVED
Notes: Once resolved, users cannot reply to this ticket. Action is logged with admin identity and timestamp.
SUPPORT_TICKETS Topic
Close a Support Ticket
Mark a support ticket as closed (stops accepting replies without full resolution)
How:
1. Open SUPPORT_TICKETS topic
2. Find the ticket you want to close
3. Click the ❌ Close button
4. Ticket status changes to CLOSED
Notes: Similar to Resolve but used when you want to end conversation without full resolution. Action is logged.
SUPPORT_TICKETS Topic
Reply to Support Ticket
Send a reply to the ticket user via bot DM. The user can then reply back via the "↩ Reply" button.
How:
1. Open SUPPORT_TICKETS topic
2. Find the ticket
3. Click the 💬 Reply button
4. Bot will DM you asking for your reply
5. Send your reply message
6. Bot posts your reply to the ticket and notifies the user via DM
7. User can click ↩ Reply in their DM to respond back
Notes:
  • Replies are captured via private bot DM (not in topic)
  • Your identity and timestamp are included with each reply
  • Users are notified via DM when admins reply
  • Users can continue the conversation via ↩ Reply button
  • All replies are persisted in snapshots
